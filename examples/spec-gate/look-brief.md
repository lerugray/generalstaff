# Look brief: template

Use this when you ask anyone (a person, an agent, a visual-check tool) to judge how a screen looks. Fill in the three fields first. Do not drop the first question.

## The owner's words

Quote the owner's own words for this feature, verbatim, with the source.

> "<owner's words>" (<where the owner said it>)

## The user

Name the user in one line: who they are and what they came to do.

<user>

## The screen

What is being judged: the path to the screenshot, page or build, and what state it is in.

<screen>

## Questions, in this order

1. Would that user get what the owner asked for from this screen? Answer yes or no, then one sentence. A screen nobody asked for is a FAIL, however clean it looks. Stop here on a FAIL and say what the owner described instead.
2. Can the user do the first step of the owner's description from this screen without help?
3. Does the screen use vocabulary the owner or the user would use? List any technical terms, setup fields, tables or dropdowns that stand in for something the owner described the software doing.
4. Only now: layout, spacing, legibility and visual polish. Note problems; do not let them outweigh questions 1 to 3.

## Reply

PASS or FAIL for question 1, then short answers to 2 to 4. Do not propose features the owner did not ask for.
